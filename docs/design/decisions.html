D10IDsUUIDNot guessable (extra protection only, not a substitute for permission checks)1, 2, 3 …
D11Moneybigint in paisaNo floating-point rounding errorsDecimal or float
D12Audit storagePostgreSQL, append-only, same transactionAtomic with the change; no second datastore to runMongoDB
D13DecisionsOwn table, separate from the audit logBusiness data that SALES needs to readAudit log only
D14DeletingApplications are never deletedPayment history must be keptSoft delete
D15MigrationsGenerated, reviewed, auto-sync offEvery schema change is explicit and reviewedAuto-sync
D16Validation timingFull validation on create and updateSubmit stays simple; drafts are always completePartial drafts, validated at submit
D17Edit historyEdits overwrite the application in placeSimple. History still comes from each submission's risk result and decision, plus audit entries naming the changed fields. Trade-off: earlier field values aren't keptSave a snapshot of the data at each submission
D18Lifecycle endpointsAction endpoints: submit, assign, decisionsEach maps to one transition with its own input, permission check and testsGeneric status update; one endpoint per decision

D20PaginationPage and limit, with total countSimple and Swagger-friendly; fine at this scaleCursor-based
D21Sessions15-minute access JWT plus a 7-day rotating refresh token, stored hashed, with reuse detectionShort-lived access with revocable sessions; a stolen refresh token is detectedAccess token only
D22Token transportJSON bodyAPI-only service; easy to test in SwaggerhttpOnly cookies (right for a browser frontend)
D23Unknown fieldsRejected with 400Clients can't set status, owner or reviewer through create or editSilently strip them
D24Login errorsOne generic message, plus rate limitingNo account discovery; slows password guessingSpecific error messages
D25Risk detail for SALESLevel only, no score or reasonsNeed-to-knowSame view for every role
