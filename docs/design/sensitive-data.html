How national ID encryption works

  • Algorithm: AES-256-GCM. It encrypts the value and also detects if anyone tampers with the stored ciphertext.
  • Random IV per value: a fresh random starting value (IV) is used every time, so the same ID encrypts to different text each time.
  • Stored format: v1:<iv>:<authTag>:<ciphertext>. The v1 labels which key encrypted the value, so keys can be swapped later.
  • The key: 32 random bytes from the env variable FIELD_ENCRYPTION_KEY. The app refuses to start if the key is missing or the wrong length. .env.example only has a placeholder, and the real key is never committed.
  • Where it happens: an injectable EncryptionService that services call explicitly, so it's visible and unit-testable rather than hidden inside the entity. The property is named nationalIdEncrypted so nobody mistakes it for plain text.
  • Who decrypts: only the risk worker. No API endpoint ever returns the full number.

Documented for production, not built here: the key held in a KMS or Vault; envelope encryption (a data key protected by a master key); a key rotation job that re-encrypts values under v2; encrypting owner email and phone too, with a keyed hash ("blind index") if they need to be searchable; a database user that can't UPDATE or DELETE audit logs; a job that deletes expired refresh tokens; and refresh tokens in httpOnly cookies once a browser frontend exists.
