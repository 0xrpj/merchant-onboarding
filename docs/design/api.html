API

Endpoints, request and response examples, owner editing, pagination and the error format.

Conventions

  • Base path: all paths below are relative to /api/v1. Swagger UI is served at /api/docs.
  • JSON: camelCase fields, timestamps in ISO 8601 UTC, and money as whole numbers in paisa, the same as the database (expectedMonthlyVolumeMinor: 150000000).
  • Auth header: Authorization: Bearer <accessToken> on every endpoint except login, refresh, logout and health.
  • Request ID: every response carries an X-Request-Id header, taken from the request or generated. The same ID appears in error bodies and audit entries.
  • Unknown fields are rejected with 400. A client can't sneak "status", "createdById" or "assignedReviewerId" into a create or edit request (mass-assignment protection).
  • Action endpoints return the updated application. Submit and retry answer 202 Accepted because the risk check continues in the background.

Editing owners

PATCH sends the whole owners list:

What you sendWhat happens
An owner with idThat owner is updated. nationalId is optional; leave it out to keep the stored one
An owner without idA new owner is added. nationalId is required
An existing owner you leave outThat owner is removed
An id belonging to a different application400. This blocks tampering with another application's owners

After the changes are applied, the list must still have 1 to 10 owners, total ownership of at most 100%, and exactly one primary contact. The same "send the whole group" rule applies to processing; top-level fields such as businessName can be sent one at a time.

Listing and pagination

GET /api/v1/applications?status=IN_REVIEW,INFO_REQUESTED&riskLevel=HIGH&unassigned=true&page=1&limit=20
  • Filters: status (one or more), riskStatus, riskLevel, assignedReviewerId, unassigned. Filters only narrow what you can already see. If Sita filters by Ram, she still only sees her own applications.
  • Paging: page defaults to 1. limit defaults to 20, with a maximum of 100. Newest first.
  • List items are a summary with no owners or risk details. Use the detail endpoint for those.
{
  "data": [
    { "id": "…", "businessName": "Himal Brew Café", "status": "IN_REVIEW", "riskStatus": "COMPLETED",
      "riskLevel": "LOW", "createdBy": { "id": "…", "fullName": "Sita" }, "assignedReviewer": null,
      "submissionCount": 1, "createdAt": "…", "updatedAt": "…" }
  ],
  "meta": { "page": 1, "limit": 20, "total": 57, "totalPages": 3 }
}

Recording a decision

POST /api/v1/applications/:id/decisions
{ "decision": "REQUEST_INFO", "note": "Registration number doesn't match the company registry" }

A note (up to 2,000 characters) is required for REJECT and REQUEST_INFO, and for APPROVE when the risk level is HIGH. Without one, the response is 400 NOTE_REQUIRED.

Error format

{
  "statusCode": 409,
  "error": "Conflict",
  "code": "INVALID_STATE_TRANSITION",
  "message": "Cannot approve an application in SUBMITTED state",

}
